# frontend-admin

E-commerce **admin dashboard** built with **React + Vite + Tailwind CSS v4**.

## Features

- 🔐 Admin-only login (checks JWT `role == "admin"`)
- 📊 Dashboard with stats, revenue, recent orders & low-stock alerts
- 🛍️ Product management — create / edit / delete, search, sale pricing
- 🎬 **Product video upload** — mp4 / webm / mov, played on the storefront product page
- 📦 Order management — view all orders (incl. guest orders) & update status
- 💳 **Bakong Wallet / KHQR settings** — Company Name, Bakong Wallet ID,
  Display Name, Currency (+ KHR rate) used on the customer payment screen
- 🏷️ Promo code management — create & activate/deactivate
- 👥 User management — change roles (user ↔ admin)
- ⚙️ Store settings — site name & logo
- ⚡ **Real-time** — orders, products, slides, alerts and settings refresh
  automatically over WebSocket (no page reload)
- 🌐 Khmer / English language toggle, 🌓 dark / light theme

## Getting started

```bash
npm install
npm run dev
```

Runs on **http://localhost:5174** and talks directly to the deployed backend
**`https://backend-e-online.onrender.com`** (the Vite dev server also proxies
`/api` and `/uploads` to it as a fallback).

To use a local backend instead, create `.env.development.local`
(git-ignored) — **not** `.env`, because Vite gives `.env.development` higher
priority than `.env`:

```
# frontend-admin-e-online/.env.development.local
VITE_API_URL=http://localhost:8000
VITE_WS_URL=ws://localhost:8000
```

Then start the backend on SQLite (no env needed → `backend-e-online/ecommerce.db`):

```bash
# from the backend-e-online/ folder
.venv/bin/uvicorn app.main:app --reload
.venv/bin/python create_admin.py admin@example.com --password 'admin12345'
```

## Making yourself an admin

1. Register an account from the customer storefront (`frontend-user-e-online`).
2. Promote it to admin:

```bash
# from the backend-e-online/ folder
.venv/bin/python create_admin.py your@email.com
```

3. Log in to the admin panel at http://localhost:5174 with that account.

## Bakong Wallet / KHQR payment settings

Go to **Settings → Bakong Wallet / KHQR payment** and fill in:

| Field               | Purpose                                                        |
| ------------------- | -------------------------------------------------------------- |
| **Company Name**    | Shown as the checkout page title / payment screen header        |
| **Bakong Wallet ID**| Your official Bakong Account ID (e.g. `yourname@acleda`) — shown to the customer on the QR screen |
| **Display Name**    | Receiver name shown to users                                    |
| **Currency**        | `USD` or `KHR` — how amounts are displayed on the payment page   |
| **KHR rate**        | Riel per 1 USD (used for KHR display, default `4100`)            |

These are stored as site settings (`payment_company_name`,
`payment_bakong_id`, `payment_display_name`, `payment_currency`,
`payment_khr_rate`) and exposed to the storefront through
`GET /api/payments/config`.

> The QR itself is generated by the KHQRcc / ABA Pay gateway configured on the
> backend (`KHQRCC_PROFILE_ID` + `KHQRCC_SECRET_KEY`). The badge in this section
> tells you whether that gateway is enabled.

## Environment variables

| Variable       | Description                                          | Default                                 |
| -------------- | ---------------------------------------------------- | --------------------------------------- |
| `VITE_API_URL` | Backend API base URL (API + uploaded media).         | `https://backend-e-online.onrender.com` |
| `VITE_WS_URL`  | WebSocket base URL for real-time updates.            | derived from `VITE_API_URL` (`wss://…`) |

Vite loads them from `.env.development` (dev) and `.env.production` (build). If
a variable is missing or empty, the code falls back to the deployed backend.
